## 1. Patch `use-paged-query.ts` — tighten `loading` type

**Find** the `UsePagedQueryResult` interface (around the `tableProps` field declaration using `Pick<TableProps<TItem>, ...>`):

```ts
tableProps: Pick<TableProps<TItem>, 'dataSource' | 'loading' | 'pagination' | 'onChange'>
```

**Replace with** explicit typing that narrows `loading` to non-optional `boolean`:

```ts
tableProps: {
  dataSource: TItem[]
  loading: boolean
  pagination: NonNullable<TableProps<TItem>['pagination']>
  onChange: NonNullable<TableProps<TItem>['onChange']>
}
```

**Note on assignment**: implementation already does `loading: query.isFetching` which is `boolean` (never undefined) — no implementation change needed. Just the type tightens.

Caller can now write `loading={tableProps.loading}` without `!!` cast.

## 5. Notes on UX subtleties

### Hide-search animation choice

`max-height` transition rather than `display: none` toggle because:

- Component stays mounted → form state preserved (typed values intact when toggled back)
- `display: none` would unmount → state lost
- 600px max-height is upper bound for current 5-field form (1 row, ~64px). Buffer accommodates wrap on narrow screens.

If a future feature page has many search fields wrapping to multiple rows, increase the cap. For Phase 5B port loop pages, 600 is plenty.

### Refresh button loading state

`loading={tableProps.loading}` ties the refresh icon's spinner to query fetch state. When user clicks refresh:

- `refetch()` triggers
- `query.isFetching` → true
- Both Table loading overlay AND refresh button spinner show
- BE responds → both clear

Consistent visual feedback. No race.

### Toolbar layout

Primary actions (Create, Delete Selected) on left, utility actions (Search toggle, Refresh) on right. Pattern matches yudao + most admin templates. `justifyContent: 'space-between'` on outer Space achieves the split.

### Tooltip for icon buttons

Search + Refresh use icon-only buttons (no text label). Tooltip provides text on hover. yudao parity + accessibility.

### Why search toggle is `type="default"` when visible vs `"primary"` when hidden

Visible state = current/active → default styling (lower emphasis). Hidden state = action available to show → primary (call-to-action). Subtle visual hint that the button toggles state.
