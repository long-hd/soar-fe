# T2.0b — i18n File Split + Type Augmentation (v2 — Option C)

> Splits flat `en.json` / `vi.json` into per-domain files for translator convenience. Runtime merges into single `translation` namespace → **zero call site changes**. Resolves tech debt #6.

---

## Decision recap

**Option C** (revised): files split per-domain, **runtime merge into single namespace**. Components keep `useTranslation()` with no args + path-style `t('appShell.profile')`.

Why this works for Soar:

- Translator-friendly file structure (1 file per domain, easy diff)
- Zero call site changes — `t('appShell.logout')` etc. continue working
- Type augmentation merges all file types → autocomplete + type-check preserved
- No mental overhead of per-component namespace registration
- Multi-ns features (lazy load, namespace fallback chain) not needed at Soar's scale

## 2. PATCH `src/shared/i18n/index.ts` (full replacement)

```typescript
import i18n from 'i18next'
import LanguageDetector from 'i18next-browser-languagedetector'
import { initReactI18next } from 'react-i18next'

// English domain files
import enCommon from './locales/en/common.json'
import enLogin from './locales/en/login.json'
import enAppShell from './locales/en/app-shell.json'
import enError from './locales/en/error.json'
import enTabRenderer from './locales/en/tab-renderer.json'
import enTagsView from './locales/en/tags-view.json'

// Vietnamese domain files
import viCommon from './locales/vi/common.json'
import viLogin from './locales/vi/login.json'
import viAppShell from './locales/vi/app-shell.json'
import viError from './locales/vi/error.json'
import viTabRenderer from './locales/vi/tab-renderer.json'
import viTagsView from './locales/vi/tags-view.json'

/**
 * i18next initialization.
 *
 * File organization (T2.0b — Option C):
 *  - Translations split into per-domain JSON files for translator + diff convenience.
 *  - Each file holds ONE top-level key that mirrors the historical flat structure.
 *  - Runtime merges all files into a single `translation` namespace via object spread.
 *  - Components call `useTranslation()` with no args + path-style keys:
 *      t('common.save'), t('appShell.logout'), t('tagsView.close'), ...
 *  - Type augmentation in `types.d.ts` provides autocomplete + key-existence checking.
 *
 * Adding a new domain: create `locales/en/<domain>.json` with `{ "<domain>": { ... } }`,
 * mirror in `vi/`, import + spread here, import + add type in `types.d.ts`.
 */

const enResources = {
  ...enCommon,
  ...enLogin,
  ...enAppShell,
  ...enError,
  ...enTabRenderer,
  ...enTagsView,
}

const viResources = {
  ...viCommon,
  ...viLogin,
  ...viAppShell,
  ...viError,
  ...viTabRenderer,
  ...viTagsView,
}

void i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: {
      en: { translation: enResources },
      vi: { translation: viResources },
    },
    fallbackLng: 'en',
    supportedLngs: ['en', 'vi'],
    nonExplicitSupportedLngs: true, // 'vi-VN' counts as 'vi'
    interpolation: { escapeValue: false },
    detection: {
      order: ['localStorage', 'navigator'],
      lookupLocalStorage: 'i18nextLng',
      caches: ['localStorage'],
    },
    returnNull: false,
    debug: import.meta.env.DEV,
  })

export default i18n
```

## 3. PATCH `src/shared/i18n/types.d.ts` (full replacement)

```typescript
import 'i18next'
import type common from './locales/en/common.json'
import type login from './locales/en/login.json'
import type appShell from './locales/en/app-shell.json'
import type error from './locales/en/error.json'
import type tabRenderer from './locales/en/tab-renderer.json'
import type tagsView from './locales/en/tags-view.json'

/**
 * Merges all per-domain JSON shapes into a single `translation` namespace,
 * matching how `index.ts` spreads them at runtime.
 *
 * Resulting type guarantees:
 *   t('common.save')           // ✅ autocompleted
 *   t('appShell.logout')       // ✅
 *   t('tagsView.closeOthers')  // ✅
 *   t('common.unknownKey')     // ❌ TS error
 *
 * Adding a new domain: import its JSON type and add to the intersection.
 */

type Translation = typeof common &
  typeof login &
  typeof appShell &
  typeof error &
  typeof tabRenderer &
  typeof tagsView

declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: 'translation'
    resources: { translation: Translation }
  }
}
```

## Notes on subtle points

### Why spread-merge instead of nested namespaces

i18next supports multi-namespace natively but adds API surface (per-component `useTranslation('ns')` calls, `ns:key` separator syntax). Single-namespace + spread merge gives the **organizational** benefit (file split) without the **API** cost.

The architectural concern multi-namespace solves (lazy-load namespace bundles over HTTP) doesn't apply to Soar — all translations bundle locally at build time.

### Why each JSON file has 1 top-level key

Spreading `{...enCommon, ...enLogin}` requires each file's top-level shape to NOT collide. By giving each file 1 unique top-level key (`common`, `login`, etc.), the spread builds a non-overlapping object — no key conflicts even as more files are added.

Alternative: keep keys at root (e.g., `common.json` = `{ save: "Save", ... }` flat). Bad — every domain's `save`/`title`/etc. would collide.

### Type intersection vs union

We use intersection (`A & B`) because the merged resource has keys from BOTH. Union would mean "one of either" — wrong for spread semantics.

The intersection produces:

```ts
{
  common: { save, cancel, ... },
  login: { title, username, ... },
  appShell: { ... },
  error: { ... },
  tabRenderer: { ... },
  tagsView: { ... },
}
```

— exactly what runtime sees.

### Vietnamese key mirror

`types.d.ts` imports type from `en/*.json` only. Vietnamese files must mirror EN structure (same keys, same nesting). No automated check. Open item A2-TD1-ish — note tracked as T2.0b-TD1.

### Future namespace additions

When Task 2 adds system-user strings:

```
locales/en/system-user.json:
{
  "systemUser": {
    "page": { "title": "User Management", ... },
    "table": { "username": "Username", ... },
    ...
  }
}
```

`index.ts` adds 2 import lines + 2 spread lines. `types.d.ts` adds 1 import + extends intersection. 4 lines of "wiring" per new domain — fast.
