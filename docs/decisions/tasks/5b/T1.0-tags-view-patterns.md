## Decisions chốt (Q1.1 → Q1.8 — Long đã vote A across the board)

| Q                     | Decision                                                                                 | Rationale (short)                                                                                                                            |
| --------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1 Tab identity      | **Full URL search string** as id, e.g. `tab=system-user&page=2`                          | Yudao analog: `route.fullPath`. Supports multi-instance detail pages (Phase 5C) without slice schema change.                                 |
| 1.2 Active tab source | **URL `?tab=` is single source of truth**; slice holds `openTabs` only, no `activeTabId` | Eliminates 2-source drift. Matches Phase 5A flat-URL philosophy.                                                                             |
| 1.3 `addTab` trigger  | **`TabRenderer` URL-effect** dispatches addTab                                           | Deep-link `/?tab=system-user` auto-adds tab. Yudao analog (`watch(currentRoute)`).                                                           |
| 1.4 Refresh mechanism | **Bump `refreshKey` in tab state; use as `<Component key={refreshKey}>`**                | Pure React remount. No `/redirect` route hack.                                                                                               |
| 1.5 Close-left/right  | **Skip** in T1; defer if requested.                                                      | Not in DoD. Most users use close-others.                                                                                                     |
| 1.6 Affix tabs        | **Schema field reserved (`closable: boolean`), UI skips** in T1.                         | No Dashboard yet. Add Phase 5C when first affix needed.                                                                                      |
| 1.7 Tab title         | **From `menu.name` at addTab time**; mutable later via `updateTitle`                     | Detail pages will override later (e.g., "Edit user: Long"). i18n menu labels = tech debt #14 (separate).                                     |
| 1.8 Switch animation  | **Jump-cut**                                                                             | Perceived speed. antd `Tabs` default = no animation between content panels (we use it as a tab bar only, content rendered by `TabRenderer`). |

## State shape

```typescript
interface TabItem {
  /** Identity: URL search string, e.g. "tab=system-user-detail&id=123". */
  id: string
  /** Menu tab_key, e.g. "system-user". Used for menu highlight + future parentTabKey resolution (#13). */
  tabKey: string
  /** Display title — captured from menu.name at addTab time. Mutable via updateTitle (Phase 5C: detail page sets "Edit X"). */
  title: string
  /** Full URL search string to restore on tab click. Same as `id` today; kept separate for forward compat. */
  search: string
  /** True for user-opened tabs; false for affix (defer T1 — always true). */
  closable: boolean
  /** Bumped to force `<Component>` remount (refresh action). Initialized to 0. */
  refreshKey: number
}

interface TagsViewState {
  openTabs: TabItem[]
}
```

**Why no `activeTabId` field**: URL `?tab=` + query params is the single source of truth. Active tab is derived in render via `searchParams.toString()` matching against `openTabs[*].id`. (See Q1.2.)

## How the pieces fit (data flow)

```
URL changes (?tab=system-user)
  ↓
react-router emits new searchParams
  ↓
TabRenderer useEffect:
  - resolve menu by tabKey
  - if valid → dispatch addTab({id: searchString, tabKey, title: menu.name, ...})
    (addTab reducer: if id already in openTabs → no-op)
  ↓
Redux updates → persists to sessionStorage
  ↓
TabBar re-renders: shows tab list, activeKey = current searchString
  ↓
TabRenderer renders <Component key={refreshKey}>
```

```
User clicks tab in TabBar
  ↓
navigate(`/?${tab.search}`)
  ↓
URL changes → same flow above (addTab is no-op, tab already exists)
```

```
User clicks (×) on tab
  ↓
TabBar onEdit handler:
  - dispatch closeTab(id)
  - if closed tab was active → navigate to neighbor (left preferred, else right, else `/`)
```

```
User right-clicks tab → Dropdown menu
  ↓
Close / Close Others / Close All / Refresh actions
  ↓
Same close logic as above for navigation; Refresh = dispatch refreshTab(id) (no navigation needed).
```
